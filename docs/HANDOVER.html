1. What it is

A touch-screen tourist information kiosk (Electron 34 + React 19 + TypeScript, CSS Modules). Windows only. One build runs at every location. Each machine is told which location it is (its kioskId, e.g. W004), and that picks the screens, the content and the features (card terminal, camera, games…).

Main features: info screens (shops, events, palaces, transport, tax-free, exchange rate, weather, flights/ferries in Jeju), AI course recommendation, AR hanbok photo booth with QR download, donation/shop web pages with card payment, footfall counting, Jeju motion games, height measurement (Jeju, ZED camera).

2. Run it on your PC

  1. Install Node 20+. Run npm install (it also rebuilds native modules for Electron).
  2. Get the real .env and secrets/service-account.json + secrets/service-account-osaek.json from the previous developer (never in git). .env.example shows every key.
  3. Set DEV_MODE=true in .env → a location switcher appears on the home screen so you can view any kiosk (W001…W202).
  4. npm run dev → app with hot reload. F12 opens DevTools.

4. How the app is wired

Google Sheets / witteria API / weather / flights
          │  (fetched by)
          ▼
  src/main/services/*  ──save──▶  SQLite  (%APPDATA%\kiosk-app\data\kiosk.db)
          │
  src/main/ipc/handlers/*   (main answers requests, pushes "changed" events)
          │
  src/preload  → window.api
          │
  renderer stores (Zustand)  →  src/layouts/<location>/*.tsx  (screens)
  • Startup (src/main/index.ts): load .env → open DB + migrations → create services → set power schedule → open window (shows cached data instantly) → start weather/flights/exchange polling → start payment agent (if the location has a card terminal) → start auto-update → refresh content in background.
  • Screens: every layout is a fixed 2160 × 3840 canvas scaled to the monitor, so Figma px = CSS px.
  • Navigation and idle: useKioskController.ts. After 3 minutes without touch the kiosk goes back to home and resets language to Korean.
  • Languages: ko / en / ja / zh. Text comes from the Localization tab of the location's Google Sheet.

Where kioskId is saved

  • File: %APPDATA%\kiosk-app\kiosk-config.json → {"kioskId":"W004"} (beta: %APPDATA%\kiosk-app-beta\).
  • Read by src/main/core/KioskConfigStore.ts. It is not in .env and not in the build, so one installer fits every location.
  • Set it on a new machine (run once, then restart the app): 
    powershell -ExecutionPolicy Bypass -File provision-kiosk.ps1 W004
    The script is also copied next to the installed app. Optional -ShopId N overrides the shop-API id (normally leave it off). -Beta for the beta install.
  • Not provisioned → falls back to the default kioskId in src/shared/constants.

7. Google Sheets in detail

Each location family has its own spreadsheet: Insadong (W001–W003), Osaek (W004), Hwaseong (W005), Jeju (W008–W010). KADA has none (its text is in layouts/kada/kadaText.ts). The sheet IDs are in GoogleSheetsSyncTransport.ts (runtime) and scripts/sync-sheet.mjs (build time) — keep both in sync.

Two ways sheets are read

  1. Build time — npm run sync:sheet downloads tabs like Localization_Insa, PalaceInfo_Insa, AICategory_* and writes typed files to src/renderer/src/data/ (raw CSV cached in sheet-cache/). These ship inside the app as the offline default. Run it before a release when content changed.
  2. Runtime — SyncService + GoogleSheetsSyncTransport read the location's Localization_* tab on every app launch and every night at 00:00 (NightSyncScheduler.ts), and save it to SQLite (translations table). The new text shows after the next reload.

How it authenticates

  • A Google service account (secrets/service-account*.json, path in GOOGLE_SERVICE_ACCOUNT_JSON). Each spreadsheet must be shared with that service account's email.
  • GOOGLE_SHEETS_ID is only an on/off switch — any value turns night sync on. Which sheet is read depends on kioskId.

Nightly job at 00:00 does

refresh shops/attractions/banners/outfits/backgrounds/games → resend failed stats → download sheet text → upload analytics → retry Drive photo uploads → prune old height rows.

9. Daily power schedule (auto shutdown)

The app sets this up by itself on every launch (src/main/core/PowerManager.ts) using Windows Scheduled Tasks, and registers itself to auto-start on login.

WhoScheduleWindows task name
W001, W002, W003, W005, W202Reboot every day at 02:00KioskAutoRestart
W004, W009, W010Shut down 22:00, start 08:00KioskShutdownAt10PM, KioskStartAt8AM
W008 (제주공항)Shut down 00:00, start 06:00KioskShutdownAtMidnight, KioskStartAt6AM
Beta buildReboot every day at 09:00KioskBetaAutoRestart
Important: Windows cannot turn on a PC that is fully powered off. For the shut-down sites, set the motherboard BIOS → "Power On by RTC Alarm" to the start time (08:00, or 06:00 on W008), otherwise the kiosk stays off in the morning. Also disable ErP / Deep Sleep if the BIOS has it, or the alarm never fires.

The SetAutoShutdown*.bat / UnsetAutoShutdown*.bat files in the repo root are the old manual way — not needed any more. To check on a machine: open Task Scheduler and look for the task names above. W009/W010 still use the 오색시장 hours (22:00/08:00) and should be confirmed with each venue.

10. Releases and auto-update

  • npm run build:win builds the installer and publishes to GitHub Releases. Kiosks update themselves (electron-updater).
  • Production kiosks check once a week (UPDATE_DAY/UPDATE_TIME, default Friday 17:00; a missed window is caught up at next start). Beta kiosks check every 15 min and only take beta releases.
  • Install happens only when the kiosk is idle (never during photo countdown / AI generation).
  • "Update now": an admin button on the witteria site; kiosks poll it every 5 min and update immediately. See docs/UPDATE_COMMAND_API.md.
  • The .env and secrets/ on your PC are baked into the installer — build from a machine with the correct production .env.
  • More: docs/AUTO_UPDATE.md.

13. Gotchas

  • README.md and PROJECT_STATE.md are outdated. Trust the code and this document.
  • @nestjs/* and serialport in package.json are for the bundled payment agent, not for the app.
  • Some code comments say night sync is at 02:00 — it is really 00:00 (NightSyncScheduler.ts).
  • The home screen does not reset on idle if it's already on home: any popup on the home screen must close itself (useInactivityReset).
  • Camera AI (MediaPipe) is bundled offline in resources/mediapipe and served via appres://; refresh with npm run vendor:mediapipe.
  • Never commit .env, secrets/, or photos.
