1. 어떤 앱인가

관광지용 터치스크린 안내 키오스크입니다 (Electron 34 + React 19 + TypeScript, CSS Modules). Windows 전용입니다. 하나의 빌드가 모든 장소에서 실행됩니다. 각 PC에는 자기가 어느 장소인지(kioskId, 예: W004)가 설정되어 있고, 이 값에 따라 화면, 콘텐츠, 기능(카드 단말기, 카메라, 게임 등)이 결정됩니다.

주요 기능: 안내 화면(상점, 행사, 궁궐, 교통, 택스리펀, 환율, 날씨, 제주 항공편/여객선), AI 코스 추천, QR로 받는 AR 한복 포토부스, 카드 결제가 되는 기부/상점 웹페이지, 유동인구 카운팅, 제주 모션 게임, 키 측정(제주, ZED 카메라).

2. 내 PC에서 실행하기

  1. Node 20 이상 설치 후 npm install (Electron용 네이티브 모듈도 함께 다시 빌드됩니다).
  2. 실제 .env와 secrets/service-account.json, secrets/service-account-osaek.json은 이전 개발자에게 직접 받습니다 (git에 없음). 모든 키 목록은 .env.example에 있습니다.
  3. .env에 DEV_MODE=true를 넣으면 홈 화면에 장소 전환 버튼이 나타나서 모든 키오스크 화면(W001~W202)을 볼 수 있습니다.
  4. npm run dev → 핫 리로드로 실행. F12로 개발자 도구를 엽니다.
명령어하는 일
npm run dev개발 모드 실행
npm run typecheck / npm run lint커밋 전 검사
npm run sync:sheet구글 시트를 받아 src/renderer/src/data/*.generated.ts 재생성 (7장 참고)
npm run build:win운영용 설치 파일 생성 (패치 버전 자동 증가)
npm run build:win:beta베타 설치 파일 (운영 버전과 같은 PC에 나란히 설치 가능)

4. 앱 동작 구조

구글 시트 / witteria API / 날씨 / 항공편
          │  (가져옴)
          ▼
  src/main/services/*  ──저장──▶  SQLite  (%APPDATA%\kiosk-app\data\kiosk.db)
          │
  src/main/ipc/handlers/*   (메인이 요청에 응답하고 "변경됨" 이벤트를 보냄)
          │
  src/preload  → window.api
          │
  화면 스토어 (Zustand)  →  src/layouts/<장소>/*.tsx  (화면)
  • 시작 순서 (src/main/index.ts): .env 로딩 → DB 열기 + 마이그레이션 → 서비스 생성 → 전원 스케줄 설정 → 창 열기(저장된 데이터로 바로 표시) → 날씨/항공편/환율 주기 조회 시작 → 결제 에이전트 시작(카드 단말기 있는 장소만) → 자동 업데이트 시작 → 백그라운드에서 콘텐츠 새로고침.
  • 화면 크기: 모든 레이아웃은 고정 2160 × 3840 캔버스를 모니터에 맞게 확대/축소합니다. 그래서 Figma px = CSS px 입니다.
  • 화면 이동과 무입력: useKioskController.ts. 3분 동안 터치가 없으면 홈으로 돌아가고 언어가 한국어로 초기화됩니다.
  • 언어: 한국어 / 영어 / 일본어 / 중국어. 문구는 장소별 구글 시트의 Localization 탭에서 옵니다.

kioskId 저장 위치

  • 파일: %APPDATA%\kiosk-app\kiosk-config.json → {"kioskId":"W004"} (베타: %APPDATA%\kiosk-app-beta\).
  • src/main/core/KioskConfigStore.ts가 읽습니다. .env에도, 빌드에도 들어있지 않기 때문에 설치 파일 하나로 모든 장소에 설치할 수 있습니다.
  • 새 PC에서 설정하기 (한 번 실행 후 앱 재시작): 
    powershell -ExecutionPolicy Bypass -File provision-kiosk.ps1 W004
    이 스크립트는 설치된 앱 폴더에도 함께 복사됩니다. -ShopId N은 상점 API id를 강제로 지정할 때만 사용합니다(보통 생략). 베타 설치는 -Beta.
  • 설정하지 않은 PC는 src/shared/constants의 기본 kioskId를 사용합니다.

7. 구글 시트 상세

장소 계열마다 스프레드시트가 따로 있습니다: 인사동(W001~W003), 오색(W004), 화성(W005), 제주(W006~W008). KADA는 시트가 없습니다(문구는 layouts/kada/kadaText.ts에 있음). 시트 ID는 GoogleSheetsSyncTransport.ts(실행 중 사용)와 scripts/sync-sheet.mjs(빌드 시 사용) 두 곳에 있으니 항상 같이 수정해야 합니다.

시트를 읽는 두 가지 방식

  1. 빌드 시: npm run sync:sheet가 Localization_Insa, PalaceInfo_Insa, AICategory_* 같은 탭을 받아 src/renderer/src/data/에 타입이 있는 파일로 만듭니다(원본 CSV는 sheet-cache/에 저장). 이 파일들은 앱에 포함되어 오프라인 기본값이 됩니다. 콘텐츠가 바뀌었다면 배포 전에 실행하세요.
  2. 실행 중: SyncService + GoogleSheetsSyncTransport가 해당 장소의 Localization_* 탭을 앱을 켤 때마다, 그리고 매일 밤 00:00(NightSyncScheduler.ts)에 읽어서 SQLite(translations 테이블)에 저장합니다. 바뀐 문구는 다음 새로고침 때 반영됩니다.

인증 방식

  • 구글 서비스 계정을 사용합니다 (secrets/service-account*.json, 경로는 GOOGLE_SERVICE_ACCOUNT_JSON). 각 스프레드시트는 이 서비스 계정 이메일과 공유되어 있어야 합니다.
  • GOOGLE_SHEETS_ID는 켜기/끄기 스위치일 뿐입니다. 값이 있으면 야간 동기화가 켜지고, 어떤 시트를 읽을지는 kioskId로 정해집니다.

매일 00:00 야간 작업 내용

상점/관광명소/배너/의상/배경/게임 새로고침 → 실패한 통계 재전송 → 시트 문구 다운로드 → 분석 데이터 업로드 → 드라이브 사진 업로드 재시도 → 오래된 키 측정 기록 정리.

9. 매일 전원 스케줄 (자동 종료)

앱이 실행될 때마다 스스로 설정합니다 (src/main/core/PowerManager.ts). Windows 작업 스케줄러를 사용하고, 로그인 시 앱이 자동 실행되도록 등록합니다.

대상스케줄Windows 작업 이름
W001, W002, W003, W005, W202매일 02:00 재부팅KioskAutoRestart
W004, W006, W007, W00822:00 종료, 08:00 시작KioskShutdownAt10PM, KioskStartAt8AM
베타 빌드매일 09:00 재부팅KioskBetaAutoRestart
중요: Windows는 완전히 꺼진 PC를 켤 수 없습니다. 22:00/08:00 장소는 메인보드 BIOS → "Power On by RTC Alarm" = 08:00으로 설정해야 합니다. 설정하지 않으면 아침에 키오스크가 꺼진 채로 있습니다.

저장소 루트의 SetAutoShutdown*.bat / UnsetAutoShutdown*.bat는 예전 수동 방식이며 더 이상 필요 없습니다. PC에서 확인하려면 작업 스케줄러에서 위 작업 이름을 찾으면 됩니다. 제주 시간(22:00/08:00)은 오색시장 시간을 그대로 쓴 것이라 장소별로 확인이 필요합니다.

10. 배포와 자동 업데이트

  • npm run build:win이 설치 파일을 만들고 GitHub Releases에 올립니다. 키오스크는 스스로 업데이트합니다(electron-updater).
  • 운영 키오스크는 일주일에 한 번 확인합니다 (UPDATE_DAY/UPDATE_TIME, 기본 금요일 17:00, 놓치면 다음 실행 때 확인). 베타 키오스크는 15분마다 확인하며 베타 릴리스만 받습니다.
  • 설치는 키오스크가 사용 중이 아닐 때만 진행됩니다 (사진 카운트다운 / AI 생성 중에는 안 함).
  • "지금 업데이트": witteria 관리자 사이트의 버튼입니다. 키오스크가 5분마다 확인하고 바로 업데이트합니다. docs/UPDATE_COMMAND_API.md 참고.
  • 내 PC의 .env와 secrets/가 설치 파일 안에 그대로 들어갑니다. 반드시 올바른 운영용 .env가 있는 PC에서 빌드하세요.
  • 자세한 내용: docs/AUTO_UPDATE.md.

12. 자주 하는 작업

하고 싶은 일방법
화면 문구 수정해당 장소 구글 시트의 Localization 탭을 수정. 키오스크는 다음 실행 / 자정에 반영. 다음 배포 전에 npm run sync:sheet도 실행.
화면 디자인 수정src/layouts/<장소>/ (컴포넌트 + .module.css). 색상은 themes/.
새 장소 추가kioskLocations.ts에 추가 → 레이아웃 선택/제작 → 시트 ID 두 곳에 추가 → PC 프로비저닝.
새 API 데이터 추가src/main/services에 서비스 → container.ts에 등록 → ipc/handlers에 핸들러 + shared/ipc에 채널 → renderer/src/store에 스토어 → 레이아웃에서 사용.
DB 변경새 마이그레이션 파일(009_…ts)을 추가. 기존 파일은 절대 수정하지 않기.
새 키오스크 설치설치 → 한 번 실행 → provision-kiosk.ps1 W00x → 영상을 C:\KioskVideos에 복사 → BIOS RTC 설정(22:00/08:00 장소) → 재시작.
키오스크 문제 확인%APPDATA%\kiosk-app\logs\ 확인. DB는 scripts/db-inspect.mjs로 조회.

13. 주의할 점

  • README.md와 PROJECT_STATE.md는 오래된 문서입니다. 코드와 이 문서를 기준으로 하세요.
  • package.json의 @nestjs/*, serialport는 포함된 결제 에이전트용이며 앱 자체에서는 쓰지 않습니다.
  • 일부 코드 주석에는 야간 동기화가 02:00이라고 되어 있지만 실제로는 00:00입니다 (NightSyncScheduler.ts).
  • 이미 홈 화면이면 무입력 초기화가 홈 화면을 다시 그리지 않습니다. 홈 화면의 팝업은 스스로 닫혀야 합니다 (useInactivityReset).
  • 카메라 AI(MediaPipe)는 resources/mediapipe에 오프라인으로 포함되어 appres://로 제공됩니다. 갱신은 npm run vendor:mediapipe.
  • .env, secrets/, 사진은 절대 커밋하지 마세요.
