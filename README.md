# Kiosk-electron

**현장 키오스크 기기에서 도는 온디바이스 앱**

## About this repository

인사동·오색시장·화성휴게소에 설치된 키오스크에서 실제로 돌아가는 Electron 앱입니다. 관광 안내, 안내 영상과 자막, AR 한복 사진 촬영, 굿즈와 기부 화면 진입까지 화면 전체를 담당합니다. 모니터 두 대를 쓰며 한 대는 고객이 보는 전체화면, 다른 한 대는 촬영 등 보조 화면입니다.

**빌드는 하나이고 지점은 기기마다 실행 시점에 정해집니다.** 현재 다섯 대가 W001부터 W005까지 번호를 달고 있고 지점에 따라 홈 화면 구성과 카드 단말 유무가 다릅니다. 지점에서 파생되는 값은 전부 설정 파일 한 곳에 모여 있으니 화면 코드에 지점을 직접 쓰지 마세요.

**오프라인 우선으로 만들어져 있습니다.** 현장 네트워크는 통제 밖이고 방화벽이 무엇을 막을지 모릅니다. 그래서 데이터를 기기 안 SQLite에 캐시해 두고, 서버로 보낼 기록은 로컬 큐에 쌓았다가 나중에 재전송합니다. 네트워크가 끊겨도 화면은 계속 돌아갑니다.

자막과 버튼 배치, 상점 정보는 admin-be에서 받습니다. 다만 **안내 영상 파일만은 앱 번들 안에 들어 있습니다.** 이 차이가 가장 자주 사고를 냅니다.

## Getting started

### Prerequisites

* **Node.js:** v20 이상
* **플랫폼 빌드 도구:** 설치 파일을 만들 때만 필요합니다

### Installation

1. **Repository 클론**

```bash
git clone https://github.com/wit-project-sku/kiosk-electron.git
cd kiosk-electron
```

2. **의존성 설치**

```bash
npm install
```

설치가 끝나면 네이티브 모듈이 Electron 버전에 맞춰 자동으로 다시 빌드됩니다. 이 과정이 실패하면 SQLite가 열리지 않으니 로그를 확인하세요.

3. **환경 변수 설정**

프로젝트 루트에 `.env` 파일을 두면 개발 중에 자동으로 읽습니다. 운영 기기에서는 OS 환경 변수로 주입하며 이미 설정된 값이 항상 우선합니다. 백엔드 주소와 외부 서비스 키가 여기 들어가고, 실제 값은 인프라 담당자에게 받습니다.

### Run Project

```bash
npm run dev
```

키오스크 화면이 뜨고 안내 영상이 재생되면 정상입니다. 개발 중에는 변경이 즉시 반영됩니다.

빌드는 `npm run build`이고 타입 검사가 함께 돕니다. 린트는 `npm run lint`, 포맷은 `npm run format`입니다. 완료를 판단할 때는 빌드를 기준으로 삼습니다.

설치 파일은 플랫폼별 명령으로 만들며 버전 번호가 자동으로 올라갑니다.

```bash
npm run build:win     # 또는 build:mac, build:linux
```

그 밖에 기기 초기 설정, 시트 동기화, 영상 동기화, 로컬 DB 확인용 스크립트가 준비돼 있습니다.

### Before You Start

**🚨 영상은 DB로 바꿀 수 없습니다.** 자막 텍스트는 API로 내려오지만 **영상 파일은 앱 번들 안**에 있고 번들 매니페스트의 파일명과 정확히 일치해야만 재생됩니다.

DB의 영상 파일명만 바꾸면 로컬에 짝이 없어서 **그 항목이 통째로 드롭되고 영상과 자막이 함께 사라집니다.** 로그에 드롭됐다는 기록만 남습니다. 영상을 바꾸려면 반드시 이 순서를 밟아야 합니다.

```
로컬에 영상 파일 추가 → npm run sync:videos → 재빌드 → 전 기기 재설치
```

**자막 텍스트만 바꾸는 것은 앱을 건드리지 않고 DB로 됩니다.** 무엇을 바꾸는지 먼저 구분하세요.

**브랜치 규칙이 있습니다.** 이 저장소는 담당 개발자가 따로 있습니다. 작업은 개인 브랜치에서만 하고 완료하면 PR로 올립니다. 기본 브랜치에 직접 머지하지 않습니다.

**지점 값을 하드코딩하지 마세요.** 좌표, 화면 구성, 카드 단말 유무 같은 지점별 차이는 전부 설정 파일 한 곳에서 파생됩니다. 화면 코드에 지점 코드를 직접 쓰면 기기가 늘어날 때 전부 찾아 고쳐야 합니다.

**앱 업데이트는 요청만 남고 결과는 확인되지 않습니다.** 관리자 웹에서 업데이트를 지시하면 앱이 폴링해 가져가지만 지점별로 실제 적용됐는지는 서버가 알 수 없습니다. 관리자 화면에는 성공처럼 보여도 실패했을 수 있습니다.

## Project Structure

```
src/
├── main/         Electron 메인 프로세스
│   ├── core/         환경 변수, 저장소, 미디어 프로토콜, 보안, 테마
│   ├── database/     better-sqlite3, 마이그레이션, 리포지토리
│   ├── services/     자막·버튼·상점·통계·번역·날씨·카메라·동기화
│   ├── ipc/          렌더러와의 통신 핸들러
│   └── windows/      창 관리
├── preload/      메인과 렌더러 사이의 안전한 다리
├── renderer/     화면. 고객용과 보조 모니터용 두 진입점
├── layouts/      지점별 홈 화면 구성
└── shared/       양쪽이 함께 쓰는 타입과 설정
```

메인과 렌더러는 엄격히 분리돼 있고 그 사이는 preload를 통한 IPC로만 오갑니다. 렌더러에서 파일이나 DB에 직접 접근하지 않습니다.

새 기능이 서버 데이터를 쓴다면 메인의 서비스에 붙이고, 오프라인에서도 보여야 한다면 로컬 캐시와 동기화 큐에 태웁니다. 각 계층의 설계 의도는 아래 아키텍처 문서에 자세히 있습니다.

## Deployment

**자동 배포가 없습니다.** 설치 파일을 만들어 현장 기기에 설치하거나, 관리자 웹에서 원격 업데이트를 지시해 앱이 스스로 받아가게 합니다.

영상이나 번들 리소스가 바뀌면 원격 업데이트만으로는 부족하고 재빌드와 재설치가 필요합니다.

배포와 기기 빌드는 요청받았을 때만 합니다.
